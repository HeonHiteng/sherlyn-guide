Write an AI project brief you can actually test

Turn an app idea into a build specification and acceptance checklist.

What you need: an AI chat tool that accepts pasted text, plus a text editor or spreadsheet. Allow 20–40 minutes. No API or paid automation required; your chat tool’s usage limits apply.

1. Start with the practice file

Download the practice TXT ↓. Open it in a text editor, copy all its contents and paste them into a new AI chat. Alternatively attach the file if your tool supports uploads. Ask the AI to confirm the source is readable before continuing.

View the practice input
Practice idea: Build a simple study timer in one HTML file. A student should choose 5, 15 or 25 minutes, start, pause and reset. It should work on phones. No account, data collection or backend. Show completion visibly; no sound is required. Reset should restore the selected duration and stop the timer.

2. Run the prompt

Send this in the same chat after the source. It specifies both the output and how to handle missing information.

Turn this idea into a build brief with: user goal, scope, explicit non-goals, UI states, state-transition rules and acceptance tests with inputs and expected results. Use plain HTML/CSS/JS in one index.html. Timer accuracy must be based on elapsed time rather than counting interval callbacks. Define what happens when changing duration during a session. Ask only questions blocking implementation; otherwise label assumptions. Do not claim implementation or tests have run.

3. Check the result

The brief must define pause, resume, reset and completion. It must distinguish a stated requirement from an assumption, and include a phone-width test. A checklist alone is not evidence that the built timer passes.

If it fails, point to the exact source line and ask for a corrected result. Check again; do not accept a confident explanation instead of matching evidence.

4. Use it for your own work

Give the reviewed brief to your coding assistant and ask it to build index.html. Open it in a browser, run each acceptance case, and report failures with expected versus actual behaviour. For a quick completion test, ask for a temporary 5-second test preset, then remove it before publishing. The worked example below is a specification, not a finished timer.

If your result looks wrong

Start a fresh chat with only the intended source and prompt. For missing output, ask the AI to return plain text or a CSV code block you can save yourself. For large files, process labelled batches and reconcile IDs and counts before combining. Remove private details you do not need before using your own data.

Optional upload help: Google’s file attachment instructions. Pasting the small practice input works without file-upload features.
